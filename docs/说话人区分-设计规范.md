# 说话人区分 · 设计规范（实验台）

> 定稿：2026-11-06 ｜ 适用：`software/local_server.py` + `software/web/index.html` + `software/speaker_id.py`
> 目标：调试台能**录入佩戴者声音**，并在实时语音里把每一句标成「本人 / 对方 / 未判定」。
> 定位：**演示级标注能力**，不是身份认证；不改七个输出 ID、不改 `{"act":"..."}` 协议、不改已定稿的触发规则。

---

## 一、先说清楚：阿里百炼里是怎么规定的（2026-11-06 查证）

### 1.1 百炼「说话人分离」= 音频内聚类，不是声纹注册

官方文档 `help.aliyun.com/zh/model-studio/qwen-speech-recognition`「说话人分离」章节：

| 能力 | 适用模型 | 参数 | 返回 |
|---|---|---|---|
| 同步整段 | `qwen-audio-3.1-asr-flash` | `speaker_diarization_enabled` | 每句 `speaker_id` |
| 异步文件转写 | Qwen-Audio-ASR-Filetrans / Fun-ASR / Paraformer | `diarization_enabled: true`，可选 `speaker_count` | 每句 `speaker_id` |

- `speaker_count` 取值 **2–100**，默认自动判断；官方说明只能「辅助算法尽量输出指定人数，无法保证」。
- 限制：**仅支持单声道音频**；启用时建议音频 ≤2 小时，否则可能失败/超时。
- 文件转写是**异步任务**：提交 → `task_id` 轮询 → 下载 `transcription_url`（有效期 24 小时），且音频需公网可访问 URL。
- 百炼 CLI 对应 `bl speech recognize --diarization --speaker-count 2`。

**我们现用的两个模型都不支持**：

- `qwen3-asr-flash`（整段版，打字/文件/Word/音频上传链路）：官方「说话人分离」章节未列入；它的 `asr_options` 只有 `language` / `enable_itn`，固定返回 `emotion`，不返回时间戳。
- `qwen3-asr-flash-realtime`（网页「按住说话」）：VAD 流式断句，返回 `transcript` + `emotion`，无 diarization 参数、无 `speaker_id`。

**更关键的语义问题**：`speaker_id=0/1` 只是「**这一段音频里**的第 0/1 个人」，是聚类编号，**跨会话不保证指向同一人**。它无法回答「这句是不是佩戴者本人」，也不能靠「录入 8 秒本人声音」来绑定。

### 1.2 真正的「声纹注册」在阿里云智能语音交互 ISI（不是百炼）

官方文档 `help.aliyun.com/zh/isi/user-guide/sdk-reference-4`「说话人识别接口说明」：

| 规定 | 值 |
|---|---|
| 音频格式 | PCM、16 bit、单声道、**16000 Hz** |
| 注册 / 更新 / 认证音频长度 | **均不得超过 30 秒**（这是上限，不是推荐时长） |
| 录入内容 | **必须朗读服务端下发的 8 位数字串**（`ApplyDigit` 获取，有效期 2 分钟），不是自由说话 |
| `speaker_id` | ≤32 字节 |
| 比对方式 | **1 : 1** 验证，返回 `score` 0–100 与 `decision` 1/0 |
| 官方明确限制 | 「**不适用于在多人对话中识别不同说话人**」 |
| 鉴权 | ISI 项目 Appkey + Token，`wss://nls-gateway-cn-shanghai.aliyuncs.com/ws/v1`，**与百炼 DashScope API Key 是两套** |

声纹识别（基础版）API 文档另给质量门槛：`reg_active_speech_length=5`（**注册有效语音 ≥5 秒**）、`verify_active_speech_length=1.5`（验证 ≥1.5 秒）、`reg_snr=12`、`reg_avg_speech_energy=0.2`，比对阈值 `vpr_threshold` 默认 45（宽松/中等/严格边界 47.5 / 55）。

> 容易混淆的第三个东西：**声音克隆 / 音色注册 `voice-enrollment`** 需要 10–20 秒干净人声，但那是给 CosyVoice TTS 复刻音色用的，返回 `voice_id`，**不是声纹识别**。

### 1.3 结论

百炼**没有**「录入 N 秒 → 实时区分本人/对方」的现成能力：

- 文件转写的 diarization：异步、离线、聚类编号、跨会话不认人；
- ISI 声纹识别：固定数字串、1:1 认证、官方明确不适用于多人对话、另需一套 key；
- 实时版 Qwen ASR：完全没有说话人字段。

因此实验台采用**本地声纹模板方案**（见 §二）。文件转写 diarization 作为「离线复核/后续可选」保留在 §七。

## 二、方案：本地声纹模板 + VAD turn 级比对

### 2.1 为什么按 turn 能对齐到「句」

Qwen 实时版用 `server_vad`（`silence_duration_ms=400`）断句，一个 `conversation.item.input_audio_transcription.completed` 对应一个说话片段。后端按 `/api/asr-rt/append` 到达顺序累积该 turn 的 PCM 块，`.completed` 到达时结算整段并清空缓冲 —— 这就是这句话的音频。`.text` 临时事件不结算。

### 2.2 录入时长与依据

| 参数 | 默认 | 依据 |
|---|---|---|
| `enroll_sec`（录音总时长） | **8 秒** | 演示节奏；落在阿里 ISI 的 30 秒上限内，也接近声音克隆 10–20 秒建议的下沿 |
| `min_active_sec`（有效语音下限） | **5 秒** | 直接对齐阿里声纹基础版 `reg_active_speech_length=5` |
| `min_tag_sec`（单句最短有效语音） | 0.4 秒 | 太短的片段不下结论，避免噪声误判 |
| VAD 有效帧门槛 | RMS > 0.012 | 静音/气声不计入有效语音 |

前端显示「有效语音 N/5 秒」进度；不足 5 秒则拒绝生成模板并要求重录。**录入时不启动云端 ASR、不消耗 key、不联网**。

### 2.3 特征与判定（可解释，非身份认证级）

```
16k PCM16 → 25ms 汉明窗 / 10ms 帧移 → 512 点 FFT → 40 维 mel 对数能量
          → DCT 取 16 维 MFCC → 有效语音帧的 均值(16) + 标准差(16) = 32 维
          → L2 归一化 → 与模板做余弦相似度
```

- 依赖：`numpy`（本机 2.5.4，已装）。**零网络、零模型文件、零新 pip 包**。
- 三态标签（契约，大小写固定）：

| `speaker` | 中文 | 条件 |
|---|---|---|
| `wearer` | 本人 | `score >= threshold`（默认 0.82） |
| `other` | 对方 | `score < unknown_below`（默认 0.65） |
| `unknown` | 未判定 | 中间区间 / 未录入 / 音频太短 / 能量过低 |

- 阈值可在 `software/config.json` 的 `speaker` 段调整；调试台直接显示每句 `score`，现场可对照调参。
- **不做**模型训练、不做活体检测、不做 1:N 识别。同性别/相近音色、麦克风变化、回声会显著影响分数，属演示边界。

### 2.4 隐私与生命周期

- 声纹模板**只存后端进程内存**（`speaker_id.STATE["template"]`），**不落盘、不写 CSV、不上传云端**。
- 后端重启即失效，需重新录入；调试台提供「清除声纹」按钮。
- 不做持久化，与心率冻结状态保持内存态的既有决策一致。

## 三、接口契约

### 3.1 HTTP（全部 POST，JSON）

| 路径 | 请求体 | 响应 |
|---|---|---|
| `/api/speaker/enroll/start` | `{}` | `{ok, seconds:8, min_active_sec:5}` |
| `/api/speaker/enroll/append` | `{audio: "<base64 PCM16 100ms>"}` | `{ok, active_ms, total_ms}` |
| `/api/speaker/enroll/finish` | `{}` | `{ok:true, active_sec, total_sec, dim:32}` 或 `{ok:false, error}` |
| `/api/speaker/clear` | `{}` | `{ok:true}` |
| `GET /api/state` | — | 新增 `speaker` 字段（见 `speaker_id.status()`） |

音频块规格与现有实时链路一致：**100 ms = 1600 采样 = 3200 字节 PCM16 小端 / 16 kHz / 单声道**，base64。

### 3.2 SSE 事件

| 事件 | 载荷 | 时机 |
|---|---|---|
| `speaker_state` | `{enrolled, enrolled_at, mode, active_ms, threshold, last}` | 录入开始/进度/完成/清除 |
| `speaker_tag` | `{speaker, score, text, active_ms}` | 每个 `.completed` 成句结算后 |

同时给既有事件扩字段（向后兼容，旧前端忽略即可）：

- `feed_piece` → `+ speaker`
- `asr_text`（`final:true`）→ `+ speaker`、`+ score`

### 3.3 判定层与 LLM

- `PIECE_SPEAKER` 与既有 `PIECE_EMO` 一样**按句绑定**：`.completed` 结算后写入，`on_sentence_ui` 同步取快照放进 `SLOWQ`，慢脑 worker 不读全局值。
- 四处 LLM 输入（触发后复核 + 三个慢脑提示词）各加一行 `该句说话人：本人 / 对方 / 未判定`，与情感行并列；**只作为上下文，不新增动作、不改判据**。
- 非语音链路（打字 / txt·md / Word / 音频上传）`speaker` 恒为 `unknown`，提示词写「未判定（非实时语音）」，行为与之前一致。

### 3.4 明确不做的事

- **不改**七个输出的触发规则。方案定稿 §二 里 `strap1 = 佩戴者说话占比>70%`、`vib1 = 对方说完后静音≥1.5s` 目前仍由规则层的「诉求重复计数 / 静音计时」实现，不受 `speaker` 标签影响。
- 把 `speaker` 接进 `vib1` / `strap1` 是**下一阶段**候选（见 §七），需要重新确认并同步定稿，本次不动。

## 四、实验台操作

1. 打开 `http://127.0.0.1:8765` → 「语音输入」面板 → **佩戴者声纹**区。
2. 点「录入本人声音（8 秒）」，对着麦克风**连续朗读提示文案**，看「有效语音 N/5 秒」进度条。
3. 8 秒自动结束；成功显示「已录入 · 有效语音 6.2 秒 / 32 维模板」，失败给出原因可重录。
4. 之后正常「按住说话」：每句字幕前出现 `[本人]` / `[对方]` / `[?]`，右侧显示 `score`。
5. 「清除声纹」清空模板；未录入时所有句子标 `[?]`，其余链路照常工作。

**降级原则**：未录入 / 云端 ASR 不通 / numpy 异常 → `speaker=unknown`，字幕、判定、下发、七个输出**全部照常**，不中断演示。

## 五、验收

| # | 检查 | 期望 |
|---|---|---|
| 1 | 未录入时说话 | 每句 `[?]`，`speaker_tag` 为 `unknown`，七个输出正常 |
| 2 | 安静 8 秒录入 | `finish` 返回 `ok:false`，提示有效语音不足 |
| 3 | 正常录入 | `ok:true`，`active_sec ≥5`，`dim=32` |
| 4 | 本人再说同一句 | `speaker=wearer`，`score ≥0.82` |
| 5 | 换一个人 / 变声说 | `speaker=other` 或 `unknown`，不误判为本人 |
| 6 | 后端重启 | `speaker.enrolled=false`，需重录；其余状态不受影响 |
| 7 | 打字喂入 | `speaker=unknown`，LLM 提示词写「未判定（非实时语音）」 |

## 七、后续可选（本次未做，需另行确认）

1. **离线复核**：把整段录音传 `qwen-audio-asr-flash-filetrans` + `diarization_enabled=true` + `speaker_count=2`，拿 `speaker_id` 与本地标签做一致性对照；代价是公网 URL + 异步轮询 + 另一套返回结构。
2. **接进判据**：用 `speaker` 真正实现 `vib1`（仅 `other` 说完后静音才提示）与 `strap1`（`wearer` 说话占比 >70%）；会改方案定稿 §二 与已定稿的演示触发顺序。
3. **换真声纹模型**：`speechbrain` / `resemblyzer` 的 d-vector 精度更高，但要装 torch（数百 MB），与「演示机零重依赖」冲突。
4. **接 ISI 声纹识别**：只适合做「佩戴者身份认证」这类 1:1 场景，需另买服务、读固定数字串，不适合对话区分。
