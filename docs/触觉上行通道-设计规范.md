## 1. 目标

佩戴者通过表带触摸区向 AI 上行 6 种手势，完成「AI→触觉→人→触摸→AI」双向闭环。所有上行信号归入 L1 自报状态层（高确定性、零推断）——这是整条流水线里**唯一不需要推断的用户输入**，语义由用户手势直接给定。

## 2. 触摸区位置与电极

- **位置**：表带把脉侧（桡侧）的**外表面**（不贴皮肤一侧），沿表带长轴一字排开
- **电极**：导电布 4 片，各约 2cm×1.5cm，间距 1.5-2cm，从腕侧到掌侧编号 E1→E4
  - 材料用带背胶的导电布胶带（采购 T1），直接裁贴，不用另外涂胶；铝箔只作应急替代（易氧化、接触电阻会漂）
- **屏蔽**：电极背衬接地箔片（guard），降低皮肤/袖口耦合噪声；铜箔胶带（采购 T2）导电背胶可兼作 guard 与电极→导线的过渡连接
- **接线**：E1→GPIO 4（T0）、E2→GPIO 13（T4）、E3→GPIO 32（**T9**）、E4→GPIO 33（**T8**）
  - 已占用引脚：25（震动）、26（继电器 A「凉」）、**14（继电器 B「热」）**、27（舵机）、21/22（I2C）——触摸避开
  - 避开启动引脚 0/2/12/15
  - 引线用 30AWG 细硅胶线（采购 T3）：普通杜邦线太硬，腕戴弯折时会把电极拽下来

## 3. 手势定义与状态机参数

**触发判据（统一）**：相对基线的偏离。设电极基线值 B，触发条件 `|当前值 − B| > B × 30%`，**方向随 core 自适应**（v1 core 触摸时数值变小，v2/IDF5 变大），固件里不许写死「高=触摸」或「低=触摸」。

| 手势 | 检测逻辑 | 参数 |
|---|---|---|
| tap1 点一下 | 任一电极短激活 | 脉冲 30-250ms，之后 400ms 静默确认 |
| tap2 点两下 | 两次 tap1 | 间隔 80-350ms（真机不限电极；仿真请在同一电极上连点） |
| long 长按 | 持续激活 | ≥800ms，触发后强制静默期 1.5s |
| swipe_up 从下往上滑 | E1→E2→E3→E4 单向序列 | 真机：全序列 ≤600ms，允许跳步（E1→E3→E4）；**仿真放宽：每步 ≤1s、全序列 ≤3.2s**（v1.2） |
| swipe_down 从上往下滑 | E4→E3→E2→E1 | 同上 |
| rub 来回摩挲 | 方向段计数 | 真机：1.5 秒内 ≥3 次反转，总时长 0.5-2.5s；**仿真放宽：≥3 个方向段（E1→E2→E1→E2 四次交替即满足），总时长 0.3-2.5s**（v1.2）；「方向」= 相邻两次激活电极的序号差符号 |

状态机要点：每个手势结束后进入 300ms 不应期；**下行输出（继电器吸合/舵机启动）触发后 300ms 内同样丢弃触摸事件**（见 §5.5）；与下行震动同时发生时触摸优先处理（用户主动 > AI 提示）。

## 4. 上行协议（协议扩展，需战略窗口已确认）

新增主题 `wrist/ui`，手势触发即发（QoS0，不重发）：

```json
{"ch":"ui","g":"tap1|tap2|long|swipe_up|swipe_down|rub","ms":<开机毫秒>}
```

- `ms` = 开机以来毫秒（`esp_timer_get_time()/1000`）。固件没有 NTP/RTC，**拿不到 unix 时间**；软件端落日志/写 CSV 时自行换算本地时间
- 软件端按幂等处理：同一手势 300ms 内的重复消息丢弃（网络层不保证不重不漏）

软件流水线对 ui 的处理（**语义 v1.3，2026-11-05 用户确认**；旧版 tap1=确认/tap2=展开/swipe=标记·切话题/rub=安抚 的语义作废）：

| 手势 | 语义 | 实现要点 |
|---|---|---|
| tap1 | **肯定**：AI 输出后 **3 秒内** tap = 对 AI 刚才动作的肯定 → 写 `feedback.csv` 训练集 + 记忆（LLM 可见）；窗口外 tap = **戳住此刻** → 写 `pins.csv`（时间戳 + 转写快照），供之后在手机上回看该时刻转写/音频 | 窗口判定在后端（`LAST_FIRE_TS`）；固件/协议不变 |
| tap2 | **否定**：同 tap1 的双分支，反馈为否定（同样进训练集/戳） | 同上 |
| long | **静音开关**（不变）：上行静音 10 分钟，固件本地静音不依赖网络。`mute_until = ms + 600000`，**断电重置为开**——已知行为，写进用户说明文档 | 不变 |
| swipe_up | **加大 AI 输出频率**：后端缩放触发冷却（x0.6，下限 2s），写入记忆让慢脑知晓 | `JUDGE.cooldown` 缩放 |
| swipe_down | **减小 AI 输出频率**：冷却 x1.5（上限 30s） | 同上 |
| rub | **摸头互动**（v1.4 由「尾巴」改为表情屏）：屏幕单眼眨+大笑。固件本地立即切表情（不依赖网络）；同时上行，后端走统一下发链路发 `{"act":"face","f":"wink"}`，并写入记忆 | 仿真/真件=Wokwi 同款 SSD1306 OLED 128×64（I2C 0x3C，SDA=21/SCL=22），眼睛动画用 FluxGarage RoboEyes 库（GPL-3.0，眼睛样式即用户参考的机器人效果；源码参考 ZHINENG-xiaoche-C3MINI main/display/roboeyes_adapter.cc） |

配套记忆系统（2026-11-05）：所有手势与反馈写 `memory.csv`；**每新增 20 行由 LLM 压缩成一条「压缩摘要」行**（`local_server.py` compressor 线程），慢脑提示词里天然可见——触摸信号由此真正进入 LLM 的历史上下文。

## 5. 可靠性要求

1. **基线自动校准**：开机校准一次 + 空闲 30 秒滚动校准（应对袖口、温度漂移）；**校准只在无下行输出时进行**
2. **宁漏勿误**：tap1 阈值从严；长按（静音）绝不误触——误触静音是灾难，漏触只是没确认
3. **降级方案**：电容方案调试超过 1 天未稳定，改用 TTP223 触摸模块 ×4（数字输出，¥2/个，已列入采购 T4），状态机逻辑不变——TTP223 的 OUT 接同款 GPIO，VCC 接 3.3V
4. 汗水/潮湿会降低灵敏度：说明文档里注明「运动后场景灵敏度下降是已知限制」
5. **输出互扰**：继电器吸合/舵机启动瞬间可能扰动 touchRead——下行输出触发后 300ms 内丢弃触摸事件，不应期与 §3 状态机共用

## 8. 验证方法与踩坑清单（U1 前置）

1. **看曲线**：Arduino IDE「串口绘图仪」同时画四路 touchRead 原始值——空戴时曲线平（漂移 <5%），手摸对应电极出现明显阶跃；四路全无反应优先查共地，再查电极背胶是否绝缘层没撕
2. **引线**：电极→面包板用 30AWG 细硅胶线过渡（先焊/缠到铜箔胶带再引出）；杜邦线直插电极处，腕戴弯折几次必脱
3. **汗/水**：手指沾水后噪声增大是 §5.4 已知限制，不是接线故障——先擦干再判断
4. **铝箔氧化**：铝箔电极放几天后接触电阻上升、灵敏度衰减，长期方案一律导电布
5. **TTP223 降级接法**：模块跳线保持出厂（A=OL，B=OS），OUT 高电平有效，VCC 接 3.3V 不是 5V；四个模块沿表带各贴一片导电布作感应盘，状态机不改
6. **误触统计口径**：空戴 30 分钟，计「软件收到 ui 消息的条数」，含 mock 通道下所有误发——这是 U2 的验收数字，别只数「真触发」
